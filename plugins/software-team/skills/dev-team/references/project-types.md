# 项目类型适配（按需取 1–2 类）

先判交付物类型，再决定产物、门禁与验证方式。**不要把非 Web 项目套成前端/CRUD 模板**；类型可叠加（如「带管理后台的 IoT 平台」= 后端 + 前端 + 嵌入式）。

| 类型 | 识别信号 | 额外产物 / 检查 | 验证重点 |
|---|---|---|---|
| Web 前端 | 浏览器页面、组件、SPA/SSR | UI 规范、可访问性、浏览器与分辨率兼容 | 构建、交互用例、可访问性、多浏览器/真机 |
| 后端服务 / API | HTTP/RPC、任务、消息、数据库 | API 契约、数据迁移与回滚、配置与密钥、可观测性 | 契约测试、集成测试、迁移演练、压测（按风险） |
| CLI / 库 / SDK | 命令行、包、公共 API | 公共 API 兼容、语义化版本、安装/升级/卸载、示例 | 语言版本矩阵、安装冒烟、向后兼容 |
| 数据 / ML | 数据管道、训练、评估、报表 | 数据契约、可复现性、评估指标、样本与隐私、离线评测 | 数据质量校验、指标回归、泄漏检查 |
| 移动 / 桌面 | App、原生/跨端、离线场景 | 权限、离线与弱网、升级、资源占用 | 真机/模拟器、权限、崩溃与升级路径 |
| 嵌入式 / 硬件交互 | 设备、固件、通信协议 | 资源约束、协议兼容、失败安全 | 台架/真机、掉电与断连、长期稳定性 |
| 基础设施 / IaC | Terraform/K8s/CI、部署脚本 | 变更计划（plan/diff）、回滚、最小权限 | plan 审阅、dry-run、回滚演练 |
| 受监管 / PII 行业 | 金融、医疗、政务、个人信息 | 审计日志、数据留存与删除、权限最小化、合规证据 | 权限矩阵、审计追溯、脱敏；合规结论由用户或专业机构确认 |

## 用法

1. 判档时选 1–2 个主类型，写进项目简报「类型」；叠加类型在计划里说明取舍。
2. 只取与本次相关的检查，不要求全表跑；不适用的维度写 `N/A` + 理由。
3. 类型不明确时按用户原话与仓库文件判断，不臆测；仍不明确问一次。
4. 类型只影响「产物与验证重点」，不改变档位、门禁分层与验收清单的通用要求。
