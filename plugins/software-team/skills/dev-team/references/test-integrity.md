# 测试完整性反作弊（一套绿测只有"没被作弊"才可信）

> 改写自 UmaDev 知识库（MIT License）的 test-integrity-and-anti-gaming 规范，按本团队口径精简。

## 为什么需要

当"让测试通过"成了目标，最省力的路径往往不是把代码改对，而是把**测试改松**。绿灯于是奖励"会绕"，而不是证明"对"。QA 与审查者判定通过前，必须先确认测试没被作弊。

## 作弊形态目录

| 形态 | 具体表现 |
|---|---|
| 硬编码输出 | 直接返回期望值，或特判测试输入 |
| 弱化/删断言 | `assertEqual` 改成 `assertTrue`、放宽容差、删关键断言 |
| skip / xfail | 给碍事用例打 `skip`/`xfail`/`ignore` 或注释掉 |
| 篡改测试框架 | 改 conftest/setup/全局 fixture/断言钩子，让失败被吞 |
| 特判可见用例 | 只让看得见的样例通过，一般情况逻辑错误 |
| 提前退出/短路 | 校验前 `return`、吞异常、`try…except: pass` |
| 无效等待/断言不传播 | 只 `await`/`sleep` 不断言、断言写在工作线程内失败被吞、`Future` 未 `get`，用"测试结束"冒充"断言通过" |
| 放宽门禁 | 调低覆盖率阈值、关必过检查、给 lint 加豁免 |
| 改基线/期望文件 | 把快照/golden 改成当前（错误）输出 |

判定原则：**通过是靠改松验证换来的，即视为未完成。**

## 结构性防线

1. **确定性校验**：核心验收用一条实现者/测试者无权修改的检查（独立 runner、固定输入→固定期望）。
2. **留出集**：保留一组作者看不到的输入/期望用于最终判定。
3. **完整性差异**：测试与门禁配置的改动必须与实现改动**分开审视**。
4. **独立复核**：由不写该实现的人执行（见 `verifier-critic.md`）。
5. **裁判复核**：结构化回答一个问句——这次是解决了问题，还是绕过了验证？

## 完整性差异盘问表

| 改动信号 | 默认判定 | 放行条件 |
|---|---|---|
| 断言被删除或放宽 | 可疑 | 有理由且不降低区分力，审查签字 |
| 新增 skip / xfail / ignore | 可疑 | 关联已登记缺陷与期限 |
| 改动测试框架/全局 fixture/钩子 | 高危 | 独立复核确认不吞失败 |
| 修改快照/golden/基线 | 可疑 | 确认是预期行为变化 |
| 调低覆盖率阈值/加 lint 豁免 | 高危 | 默认拒绝 |
| 实现对测试输入特判/硬编码 | 作弊 | 不放行 |

## 团队落点

- **QA**：测试报告必须包含「测试改动审查」一节，逐条对照上表；命中"作弊"或"高危"→ 路由判定不得为 NoOne。改动涉及并发/异步时，同时抽查既有测试是否存在无效等待或断言不传播。
- **审查者**：diff 中凡涉及测试文件与测试配置，按上表**抽查**并在发现中标注 `test-integrity`；全量判定由 QA 主查，发现 QA 遗漏时才展开。
- **主理人**：QA 报告无该节、或该节结论与发现矛盾时，退回 QA 重出。
