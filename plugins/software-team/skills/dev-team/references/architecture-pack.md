# 架构包（按需）

## 目的

架构包用于复杂系统或新系统的架构设计，不用于单模块小改动。由一名架构师按需读取相关章节，必要时只加安全/部署评审；不默认组 8 人架构团。

## 何时使用

- 新系统、跨模块、动公开 API/数据模型、多端、多租户、强安全/合规要求。
- 单模块/单点改动不用本包，用精简设计：目标、改动点、接口、风险、验证。

## 五类交付物（按需取用）

### 1. 业务架构
- 业务边界、角色、核心流程、MVP 范围、明确不做、成功指标。
- 输出：一页业务架构 + 范围表。

### 2. 系统架构
- 模块拆分、依赖方向、接口契约、数据模型、错误处理、可观测性。
- 输出：模块图 + 接口表 + 数据表 + 关键时序。

### 3. 部署架构
- 资源拓扑、环境、CI/CD、容量、回滚、成本。
- 输出：部署图 + 环境表 + 回滚步骤。

### 4. 安全架构
- 威胁模型（STRIDE）、认证/授权、密钥管理、数据分级、运行时防护、审计日志。
- 输出：威胁表 + 控制措施 + 未覆盖风险。

### 5. UserStory / 验收
- 角色场景、Given/When/Then 或 EARS 验收标准、非功能需求。
- 输出：UserStory 表 + 验收清单，直接对接 `acceptance-checklist.md`。

## 精简 Gate

| Gate | 检查 | 不通过 |
|---|---|---|
| G0 范围 | 目标、边界、不做、成功指标明确 | 回需求澄清 |
| G1 业务 | 业务架构与范围一致 | 回业务架构 |
| G2 系统 | 模块/接口/数据/错误处理齐全 | 回系统设计 |
| G3 部署+安全 | 拓扑、回滚、威胁模型、密钥/日志齐全 | 回对应设计 |
| G4 交付 | 术语/引用一致，验收清单可执行 | 回对应文档 |

## 断点与恢复

- 每个 Gate 的状态、产物路径、未决问题写入 `project-brief.md`。
- 恢复时从最近一个已通过 Gate 的下游继续，不整体重跑。
- 并行设计（如部署+安全）必须由主理人中转，不直连；交叉一致性逐项核对。

## Token 规则

- 架构师只读本次相关章节；不要求一次输出五份文档。
- 传 `project-brief.md` + 必要上游路径，不传全文。
- 复杂架构才启用人工审核 Gate；中小任务用精简设计 + 一次审查。
