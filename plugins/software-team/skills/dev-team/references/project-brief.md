# 项目简报

## 目的

项目简报是主理人维护的单一事实源，用来替代「每次派发都传完整上游产出」。派发时传「简报路径 + 本次相关段落 + 验收清单 + 必要文件路径」，成员按需读文件，不重复复制全文。

## 模板

小任务可内联为 6 行；中大型任务落盘到 `docs/project-brief.md`。

```markdown

- 做：
- 不做：

- 项目规则/门禁：
- 交付形态：工作区 / 分支+提交 / PR / 合并
- 环境/依赖服务：

## 4. 关键决策（ADR 摘要）
| 日期 | 决策 | 理由 | 影响 |
|---|---|---|---|

## 5. 接口/数据契约
- 关键 API/数据结构：
- 兼容性要求：

## 6. 验收清单
- 见 `acceptance-checklist.md` 实例（路径或内联）

## 7. 当前状态
- 档位/模式：
- 当前切片：
- 已完成：
- 下一步：
- 阶段账本：<阶段> → <产物路径> → <门禁结论/证据命令>（每完成一个阶段追加一行；无产物写「不适用 + 理由」）
```

## 维护规则

1. **主理人维护**：成员不修改简报；有不同意见写进报告，由主理人更新。
2. **按切片更新**：每完成一个切片/阶段，更新「当前状态」「阶段账本」「已审 SHA」「未决问题」；阶段账本必须写产物路径与门禁结论，没有产物写「不适用 + 理由」。
3. **只做索引与决策记录**：简报不替代 PRD/设计/代码；详细内容留在对应文件。
4. **小任务内联**：目标、范围、约束、验收、状态、未决，6 行即可，不强制落盘。
5. **派发规则**：传简报路径 + 本次相关段落 + 验收清单；只有成员无法读文件或明确要求时才附全文。
6. **测试交接**：使用 qa-team 时，第 10 节必须填到可独立执行的程度（含计数口径、环境写权限、探针阈值、需求口径来源、部分验证接受口径、门禁凭据与链接六项，缺一先问用户，不猜）；qa-team 未安装时留空，不阻塞交付。两边字段冲突时由双方主理人裁决，裁决后各自主理人回写本方简报，成员不直接改简报。
7. **事实断言可核**：简报中的计数、编号、范围断言（如「22 个存量 Issue（#1–#22）」）写明数据来源与截至时间；未经你核验的标「未核验」，成员以实际读取为准（实测：简报编号口径与实际差 1（本仓库无 #1），由审查者作为 MINOR 发现纠出）。

## 禁止

- 不要把简报写成第二份 PRD。
- 不要每次派发都复制全文；复制全文等于没有简报。
- 不要让成员各自维护一份「自己的简报」。
