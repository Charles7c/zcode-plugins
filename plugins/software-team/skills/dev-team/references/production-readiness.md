# 生产就绪评分卡

交付终检时由审查者填写；本次未派审查者时由 QA 填写；两者都未派则标「不适用」并写理由。主理人把低分项写进交付概览。评分不是目的，**暴露未验证面**才是。

## 评分维度（6 维，每项 0–3 分，满分 18）

| 维度 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| 功能 | 核心流程跑不通 | 主要流程可用，边界缺失 | 主要+边界可用 | 需求池 P0/P1 全覆盖且有证据 |
| 测试 | 无测试或测试未跑 | 有测试但覆盖不足 | 关键路径有测试且实跑通过 | 关键路径 + 错误路径 + 回归全绿 |
| 安全 | 存在高危问题 | 有未处理的中危项 | 认证/授权/输入校验到位 | 通过安全清单（OWASP 主要项）且无遗留 |
| 性能 | 未评估且有明显风险 | 未评估但风险低 | 关键路径有基本验证 | 有量化证据（耗时/查询数/内存） |
| 可运维 | 无法启动/无日志 | 能启动，缺日志与配置说明 | 有启动方式、日志、环境变量说明 | 含健康检查、回滚方案、数据备份 |
| 文档 | 无 | 只有零散说明 | README 含启动与结构 | README + 变更说明 + 已知限制齐全 |

## 分制锁定

- 只允许 `x/18`（6 维）或 `x/12`（裁剪 2 维）；裁剪超过 2 维时写明可用满分，再按 `可用满分 × 0.78 / × 0.56` 折算。
- 必须逐维列出得分（6 行或裁剪后的行）；只给总分视为无效评分，退回重填。
- 禁止自创 60 分制、百分制，或把七维审查表另算一套总分。
- 评分档（上线就绪 / 可交付但需跟进 / 不可交付）与审查结论（`PASS / PASS_WITH_MINOR / BLOCK / SCOPE_UNCONFIRMED`）是两套值，必须分开写：「评分 x/18，档位：…」与「审查结论：…」。`SCOPE_UNCONFIRMED` 不评分；写成「50/60（PASS_WITH_MINOR）」属口径错误，按未评分处理。

## 判定规则

维度裁剪后按实际满分折算，不得沿用 6 维阈值（否则裁剪后永远达不到「上线就绪」）：

| 结论 | 6 维（满分 18） | 裁剪 2 维后（满分 12） |
|---|---|---|
| 上线就绪 | 无 0 分项，总分 ≥ 14，且安全项 ≥ 2 | 无 0 分项，总分 ≥ 9，且安全项 ≥ 2 |
| 可交付但需跟进 | 无 0 分项，总分 ≥ 10 | 无 0 分项，总分 ≥ 7 |
| 不可交付 | 任一维度 0 分，或安全项 ≤ 1 分 | 同左 |

「可交付但需跟进」的低分项必须逐条列入交付概览的「遗留与风险」。裁剪超过 2 维时，按「可用满分 × 0.78（上线就绪）/ × 0.56（可交付）」四舍五入折算。

## 证据要求

每个 ≥2 分的项必须能追溯到证据（命令输出、测试报告、文件路径）；证据不足的按低一档计，完全没有证据的维度按 0 分计。

## 例外

可整体裁剪的维度仍限两维（如无服务端的 CLI/库可裁剪「可运维」，一次性工具可再裁剪「文档」），维度内不适用项写 N/A 不计分；安全与测试不可裁剪。裁剪须逐项写理由，并按实际可用维度折算阈值。
