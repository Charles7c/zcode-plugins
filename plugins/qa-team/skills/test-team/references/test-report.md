# 测试报告（结论先行，证据可复核）

## 模板

```markdown
# 测试报告：<项目/版本/需求>

## 结论
- 放行 / 阻塞 / 部分验证
- 一句话理由：

## 范围与环境
- 仓库/commit：
- 环境/账号/租户：
- 测试类型：
- 不测范围：

## 覆盖
- 用例：总计 X | 通过 Y | 失败 Z | 阻塞 W | 未执行 V
- 关键路径/接口：
- 未测项与原因：

## 缺陷
| ID | 标题 | 严重度 | 复现 | 证据 | 影响 | 建议 |
|---|---|---|---|---|---|---|

## 安全
- 扫描：依赖 / SAST / DAST / 密钥
- 权限矩阵：认证 / 垂直 / 水平 / 租户 / 数据权限
- 未修复项与结论：

## 回归
- 受影响路径：
- 相邻未受影响路径：
- 全量/冒烟结果：

## 证据
- 报告路径：
- 命令/输出：
- 截图/trace/日志：

## 残余风险
- <明确列出；无则写「无」>

## 下一步
- 修复 owner：
- 重测范围：
- 放行建议：
```

## 规则

1. **结论只能是**：放行 / 阻塞 / 部分验证；有未测项时不得写「全部通过」。
2. **未测 ≠ 通过**：未执行、阻塞、模拟验证必须单列，不能并入通过。
3. **证据可复核**：命令 + 输出摘要，或用例 + 截图/trace/日志；没有证据的结论不成立。
4. **缺陷分级**：Critical / High / Medium / Low；写清复现、影响、证据、建议。
5. **缺陷定性**：
   - 需求未实现：验收标准明确要求但没做到；
   - 缺陷：实现与原定行为不一致；
   - 优化建议：需求未要求，体验/惯例改进；
   - 环境/工具问题：不是产品缺陷，单独列；
   - 测试 Bug：测试自身错误，不进产品缺陷。
6. **不泄露凭据**：账号写脱敏标识；密码、token、验证码、Cookie 不进报告/截图/日志。
7. **报告可读**：先结论，再统计，再明细；不堆日志；未参与测试的人能看懂。
8. **回传 dev-team**：结论按放行/阻塞/部分验证；阻塞项对应源码 Bug；部分验证项与未测项列入残余风险，不写成「全部通过」。

## 测试完整性（防作弊）

检查本次测试资产是否被改松：

- 断言是否被删除/弱化/放宽；
- 是否新增 `skip`/`xfail`/`ignore`；
- 是否修改测试框架/全局 fixture/钩子；
- 是否改写快照/golden/基线；
- 是否对测试输入特判/硬编码；
- 是否调低覆盖率/检查阈值。

命中「作弊」或「高危」→ 报告不得给放行结论，打回执行者说明理由。

## 报告长度

- 首屏：结论、范围、统计、缺陷摘要、残余风险；
- 明细：用例结果、证据、扫描报告放附录/折叠；
- 不贴无关日志、不复制需求原文、不写空表格。
