# 测试策略（先定风险，再定范围）

## 目的

测试策略回答三个问题：**测什么、不测什么、什么算通过**。没有策略就执行，等于凭感觉铺用例。

## 风险矩阵

按「影响 × 发生概率」排序，先测高风险：

| 影响 \ 概率 | 高 | 中 | 低 |
|---|---|---|---|
| 高（资金/权限/数据丢失/核心链路） | P0 必测 | P0 必测 | P1 |
| 中（主要功能/跨模块） | P0 必测 | P1 | P2 |
| 低（文案/样式/边缘） | P1 | P2 | 观察项 |

高风险信号：认证、支付、数据迁移、权限/租户、并发、缓存、依赖升级、公开 API、跨模块契约。

## 测试类型

| 类型 | 证明什么 | 成本 | 默认 |
|---|---|---|---|
| 接口/契约 | 入参、出参、状态码、权限、租户隔离 | 低 | 优先 |
| 后端集成 | DB/缓存/迁移/事务/并发 | 中 | 有基础设施时 |
| E2E/UI | 用户可见关键路径 | 高 | 只覆盖关键路径 |
| 安全 | 认证、越权、注入、上传、敏感数据 | 中 | 发版前必做基线 |
| 回归 | 变更没有破坏既有行为 | 中 | 按变更选型 |
| 探索性 | 未知问题 | 高 | 人做，AI 辅助 |

**测试金字塔**：接口 > 集成 > E2E。能用接口证明的，不用 UI；能用一条用例证明的，不铺三条。

## 范围与不测

写清：

- 本次覆盖的模块/路径/接口/角色；
- 明确不测的范围与原因（需求未要求、环境不具备、风险低）；
- 依赖的外部服务与替代方案。

## 环境与数据

- 环境：独立测试环境，不使用生产；稳定服务器用于夜间回归。
- 数据：独立租户/前缀；每次运行可重建；结束清理；不改系统内置数据。
- 账号：测试账号按角色/租户隔离；密码只在运行时使用。

## 退出标准

1. P0 用例全部通过；
2. P1 失败有明确结论（修复/接受/延期）；
3. 无 Critical/High 安全问题未处理；
4. 未测项与残余风险已列出并被接受；
5. 报告能让未参与测试的人判断“能不能放行”。

## 项目类型适配

- Web/管理后台：接口回归 + 关键路径 E2E + 权限矩阵。
- 纯后端/API：接口契约 + 集成 + 认证/租户；不做 UI。
- CLI/库：命令输出/退出码/契约测试；不做浏览器。
- 数据/ML：数据质量、指标、可复现性；不做 UI 断言。
- 桌面/移动：安装/升级/核心路径；按平台能力取证据。
- IaC：plan/diff/策略校验；不直接 apply 生产。

## 测试资产布局

```
testing/
  test-brief.md          # 输入契约
  test-strategy.md       # 风险矩阵与范围
  test-design.md         # 用例设计
  api/                   # 接口用例、认证助手、fixtures
  integration/           # 后端集成（Testcontainers/JUnit）
  e2e/                   # 页面对象、关键路径、认证态
  security/              # 扫描配置、权限矩阵
  reports/               # HTML/JUnit、截图、trace
```

- 测试资产跟产品仓库同源管理；独立测试仓库只在跨项目复用时拆。
- 测试代码与产品代码分目录；测试数据用独立租户/前缀。
- 报告与证据可被 CI 归档；不提交大文件/截图到仓库。

## 禁止

- 没有风险矩阵就铺全量用例；
- 把“测试类型清单”当必测清单；
- 编造 SLA、并发量、性能指标；
- 用生产环境做破坏性测试。
